Lesson Introduction

Learn how a datapath stores, moves and processes digital data.

A datapath is one of the fundamental building blocks of a digital system. It contains the hardware responsible for storing, transferring and processing data.

In this lesson, we will gradually build an understanding of datapath components and then combine them into practical RTL designs.

Learning Objectives

By the end of this lesson, you should be able to:

🧠 Understand Datapaths

Explain what a datapath is and why it is required in digital systems.

📦 Identify Components

Understand the role of registers, multiplexers, ALUs, buses and other datapath components.

⚡ Understand Data Movement

Understand how data moves between registers and processing units.

💻 Write RTL

Implement basic datapath structures using synthesizable Verilog RTL.

1. What is a Datapath?

Understanding how digital systems move and process data.

Definition

A datapath is the part of a digital system that stores, moves and processes data.

It is typically built using components such as registers, multiplexers, arithmetic units and logic units.

Simple Datapath Concept 


        Input Data
             |
             v
      +-------------+
      |   Register  |
      +-------------+
             |
             v
      +-------------+
      |     ALU     |
      +-------------+
             |
             v
      +-------------+
      |   Register  |
      +-------------+
             |
             v
        Output Data

For example, a datapath could read two values from registers, perform an addition using an ALU, and store the result in another register.

Typical Datapath Components

  • Registers — store data.
  • Multiplexers — select between different data sources.
  • ALU — performs arithmetic and logical operations.
  • Shifters — shift or rotate data.
  • Buses — carry data between components.

Key Idea

The datapath is responsible for storing, moving and processing data.

Control logic determines how the datapath should operate.

2. Datapath vs Control Path

Understanding the difference between data processing and control logic.

What is the Datapath?

The datapath contains the hardware that stores, moves and processes data. It performs operations such as addition, subtraction, comparison, shifting and logical operations.

What is the Control Path?

The control path generates control signals that determine how the datapath should operate. It decides which operation should be performed and when data should be transferred between different components.

Simple View 


                 Control Inputs
                       |
                       v
               +---------------+
               | Control Logic |
               +---------------+
                       |
                Control Signals
                       |
                       v
               +---------------+
               |    Datapath   |
               |               |
Input Data --->| Registers     |
               | MUX           |
               | ALU           |
               | Registers     |
               +---------------+
                       |
                       v
                  Output Data

Example

Suppose a processor needs to perform: 


R3 = R1 + R2

The datapath contains the registers and ALU required to perform the addition. The control path generates signals that select R1 and R2, select the addition operation and enable the destination register R3.

Datapath and Control Path Relationship

Datapath Control Path
Stores data Generates control signals
Processes data Determines which operation occurs
Contains registers and ALU Controls datapath components
Moves data Controls when data moves

Key Idea

Datapath = What happens to the data.

Control Path = When and how it happens.

4. Registers in a Datapath

Understanding how registers store and transfer data in a datapath.

What is a Register?

A register is a group of flip-flops used to store multiple bits of digital data. For example, a 32-bit register contains 32 storage elements and can hold a 32-bit value. 


             Clock
               |
               v
        +-------------+
Data -->|  32-bit     |--> Output
        |  Register   |
        +-------------+

Why Are Registers Important?

Registers provide storage points within a datapath. They allow data to be captured on a clock edge and used during later clock cycles.

For example: 


Clock Cycle 1:

R1 = 10
R2 = 20


Clock Cycle 2:

ALU performs:

R1 + R2 = 30


Clock Cycle 3:

R3 = 30

Register Enable

A register may have an enable signal that determines whether new data should be captured. 


always @(posedge clk) begin

    if (enable)
        data_reg <= data_in;

end

When enable = 1, the register captures the input data at the active clock edge. When enable = 0, the register retains its previous value.

Register with Reset 


always @(posedge clk) begin

    if (reset)
        data_reg <= 8'b0;

    else if (enable)
        data_reg <= data_in;

end

Here, reset initializes the register to zero. The enable signal then controls whether new data is stored.

Registers in a Datapath 


             +--------+
             |  Reg A |
             +--------+
                  |
                  |
                  v
             +---------+
             |   ALU   |
             +---------+
                  |
                  |
                  v
             +--------+
             |  Reg B |
             +--------+

The first register can provide an operand to the ALU, while another register can capture the ALU result. This creates a clocked data-processing path.

Register vs Combinational Logic

Register Combinational Logic
Stores data Processes data
Controlled by a clock No storage
Output changes according to stored value Output depends on current inputs
Used between processing stages Used for operations such as addition and selection

Key Idea

Registers provide the storage points that separate datapath operations across clock cycles.

They are fundamental to building synchronous RTL datapaths.

5. Multiplexers in a Datapath

Understanding how multiplexers select data paths inside a digital system.

What is a Multiplexer?

A multiplexer (MUX) is a combinational circuit that selects one input from multiple data sources and connects the selected input to its output. The selection is controlled by one or more select signals.

2-to-1 Multiplexer 


             +---------+
A ---------->|         |
             |   MUX   |------> Y
B ---------->|         |
             +---------+
                  ^
                  |
               Select

For a 2-to-1 MUX: 


Select = 0  →  Y = A

Select = 1  →  Y = B

Verilog Implementation 


module mux2to1 (

    input  wire a,
    input  wire b,
    input  wire sel,

    output wire y

);

assign y = sel ? b : a;

endmodule

The conditional operator provides a simple way to describe a 2-to-1 multiplexer.

MUX in a Datapath

A multiplexer becomes especially important in a datapath because multiple sources may need to provide data to the same processing unit. 


              +--------+
Reg A -------->|        |
               |        |
Reg B -------->|  MUX   |------> ALU Input
               |        |
Constant ----->|        |
              +--------+
                   ^
                   |
              Select Signal

The control logic determines which source is connected to the ALU.

Example

Suppose an ALU can receive either the value from register R1 or register R2. 


sel = 0  →  ALU input = R1

sel = 1  →  ALU input = R2

Changing the select signal changes which register supplies the data.

4-to-1 Multiplexer

A larger datapath may need to select one of four different sources. A 4-to-1 MUX requires two select bits. 


             +---------+
A ---------->|         |
B ---------->|         |
C ---------->|   MUX   |------> Y
D ---------->|         |
             +---------+
                ^   ^
                |   |
              S1   S0
S1 S0 Selected Input
0 0 A
0 1 B
1 0 C
1 1 D

Why MUXes Matter in Datapaths

  • Select between different registers.
  • Select between different ALU operands.
  • Select between immediate values and register values.
  • Select between different result sources.
  • Control the movement of data through the datapath.

Key Idea

A multiplexer controls which data source is connected to a datapath operation.

The control path provides the select signals, while the datapath carries the selected data.

6. Arithmetic Logic Unit (ALU)

Understanding the processing unit at the center of many datapaths.

What is an ALU?

An Arithmetic Logic Unit (ALU) is a combinational circuit that performs arithmetic and logical operations on input data. The operation performed by the ALU is selected using control signals.

Basic ALU Structure 


             A --------\
                        \
                         +---------+
             B -------->|   ALU   |-----> Result
                         +---------+
                              ^
                              |
                         Operation
                         Select

Common ALU Operations

Operation Example Result
ADD 10 + 5 15
SUB 10 - 5 5
AND 1010 & 1100 1000
OR 1010 | 1100 1110
XOR 1010 ^ 1100 0110
Compare A == B Condition

ALU Operation Select

The ALU can use an operation-select signal to determine which operation should be performed. For example, a simple 3-bit control signal could represent: 


000 → ADD

001 → SUB

010 → AND

011 → OR

100 → XOR

The exact encoding is a design choice and can vary between different architectures.

Simple Verilog ALU 


module simple_alu (

    input  wire [7:0] a,
    input  wire [7:0] b,
    input  wire [2:0] op,

    output reg [7:0] result

);

always @(*) begin

    case (op)

        3'b000:
            result = a + b;

        3'b001:
            result = a - b;

        3'b010:
            result = a & b;

        3'b011:
            result = a | b;

        3'b100:
            result = a ^ b;

        default:
            result = 8'b0;

    endcase

end

endmodule

ALU Inside a Datapath

The ALU usually works together with registers and multiplexers. Registers provide operands, multiplexers select the appropriate inputs, and the ALU performs the requested operation. 


          +--------+
          | Reg A  |
          +--------+
               |
               v
            +-----+
            | MUX |
            +-----+
               |
               v
          +---------+
          |   ALU   |------> Result
          +---------+
               ^
               |
            +-----+
            | MUX |
            +-----+
               ^
               |
          +--------+
          | Reg B  |
          +--------+

ALU and Control Path

The control path generates the ALU operation-select signal. For example: 


Control Logic
      |
      | ALU Operation
      v
     +-----+
     | ALU |
     +-----+
       |
       v
    Result

This allows the same ALU hardware to perform different operations depending on the control signals.

Key Idea

The ALU performs the actual arithmetic and logical processing, while the control path determines which operation the ALU performs.

7. Register + ALU Datapath

Combining registers, multiplexing and an ALU into a simple datapath.

Building the Datapath

A practical datapath combines multiple hardware components so that data can be stored, selected, processed and stored again. A simple example contains two source registers, an ALU and a destination register. 


              +---------+
              |  Reg A  |
              +---------+
                   |
                   |
                   v
              +---------+
              |         |
              |   ALU   |-------> ALU Result
              |         |
              +---------+
                   ^
                   |
              +---------+
              |  Reg B  |
              +---------+
                   
                   |
                   v

              +---------+
              |  Reg C  |
              +---------+

Example Operation

Suppose: 


Reg A = 10

Reg B = 20

Operation = ADD

The ALU receives the two operands and performs: 


10 + 20 = 30

The result can then be captured into the destination register: 


Reg C = 30

Clocked Operation

The ALU itself is combinational logic, while the registers are clocked storage elements. Therefore, the datapath can operate across clock cycles. 


Clock Cycle 1

Reg A = 10
Reg B = 20


        ↓


Clock Cycle 2

ALU calculates:

10 + 20 = 30


        ↓


Clock Cycle 3

Reg C captures:

Reg C = 30

Simple RTL Example 


module register_alu_datapath (

    input wire clk,
    input wire reset,
    input wire enable,

    input wire [7:0] data_a,
    input wire [7:0] data_b,

    output reg [7:0] result

);

reg [7:0] reg_a;
reg [7:0] reg_b;

wire [7:0] alu_result;


// Input Registers

always @(posedge clk) begin

    if (reset) begin

        reg_a <= 8'b0;
        reg_b <= 8'b0;

    end

    else if (enable) begin

        reg_a <= data_a;
        reg_b <= data_b;

    end

end


// ALU

assign alu_result = reg_a + reg_b;


// Result Register

always @(posedge clk) begin

    if (reset)

        result <= 8'b0;

    else if (enable)

        result <= alu_result;

end

endmodule

How the RTL Works

  1. reg_a stores the first input value.
  2. reg_b stores the second input value.
  3. The combinational ALU performs the addition.
  4. alu_result contains the calculated result.
  5. The result register captures the ALU output on the clock edge when enable is active.

Datapath View 


 data_a ──> [Reg A] ──┐
                      │
                      v
                    [ ALU ] ──> [Result Reg] ──> result
                      ^
                      │
 data_b ──> [Reg B] ──┘

                     ^
                     |
                  Control
                 (enable)

Important RTL Concept

Combinational logic performs the calculation, while registers provide clocked storage between datapath operations.

This combination of registers + combinational logic + registers is one of the fundamental structures used in synchronous RTL design.

8. Data Movement Between Registers

Understanding how data is transferred between registers through a datapath.

Register-to-Register Data Transfer

In a synchronous datapath, data is commonly transferred from one register to another on a clock edge. Combinational logic such as an ALU or multiplexer may be present between the registers. 


        +---------+
        |  Reg A  |
        +---------+
             |
             v
       Combinational
          Logic
             |
             v
        +---------+
        |  Reg B  |
        +---------+

The first register provides data to the combinational logic. The resulting value is then captured by the destination register on the active clock edge.

Simple Register Transfer

Consider the operation: 


R2 <= R1;

At the active clock edge, the value stored in R1 is captured by R2. 


Before clock edge:

R1 = 25
R2 = 10


After clock edge:

R1 = 25
R2 = 25

Verilog Example 


always @(posedge clk) begin

    if (reset)

        r2 <= 8'b0;

    else if (enable)

        r2 <= r1;

end

The nonblocking assignment is used because this is sequential logic that operates on a clock edge.

Register Transfer Through an ALU

Data can also be modified before being stored in the destination register. For example: 


R3 <= R1 + R2;

The datapath performs the following operation: 


        R1 --------\
                    \
                     +---------+
        R2 -------->|   ALU   |------> R3
                     +---------+
                         ^
                         |
                       ADD

Here:

  • R1 provides the first operand.
  • R2 provides the second operand.
  • The ALU performs the addition.
  • R3 captures the result.

Register Transfer Through a MUX

A multiplexer can allow a destination register to receive data from different sources. 


R1 --------\
            \
R2 ----------> MUX -----> Destination Register
            /
ALU Result -/

              ^
              |
           Select

The select signal determines which source reaches the destination register.

Example RTL 


always @(*) begin

    case (sel)

        2'b00:
            next_data = r1;

        2'b01:
            next_data = r2;

        2'b10:
            next_data = alu_result;

        default:
            next_data = 8'b0;

    endcase

end


always @(posedge clk) begin

    if (reset)

        destination <= 8'b0;

    else if (enable)

        destination <= next_data;

end

Clock-to-Clock Data Movement 


Clock Cycle N

        R1
         |
         v
      Combinational
         Logic
         |
         v

Clock Cycle N+1

        R2

This clocked structure is fundamental to synchronous RTL design. The combinational logic calculates the next value, while the destination register captures that value at the clock edge.

Key Idea

Datapath operations are often described as register-transfer operations: data moves from source registers, passes through combinational logic, and is captured by destination registers.

9. Control Signals and Datapath

Understanding how control logic directs datapath operations.

Why Does a Datapath Need Control Signals?

A datapath contains several components that can perform different operations. Control signals tell these components what to do and when to do it. For example, control logic may determine:

  • Which register should provide data.
  • Which MUX input should be selected.
  • Which ALU operation should be performed.
  • Which register should capture a result.

Control Signals in a Simple Datapath 


                    Control Logic
                         |
          +--------------+--------------+
          |              |              |
          v              v              v
      MUX Select     ALU Operation   Reg Enable
          |              |              |
          +--------------+--------------+
                         |
                         v
                  +-------------+
                  |   DATAPATH  |
                  |             |
                  | Registers   |
                  | MUX         |
                  | ALU         |
                  +-------------+

Common Datapath Control Signals

Control Signal Purpose
Register Enable Allows a register to capture new data.
MUX Select Selects which data source reaches the next stage.
ALU Operation Selects the arithmetic or logical operation.
Load Enable Controls when data is loaded into a storage element.
Write Enable Controls whether a destination register or memory location is written.

Example: R3 = R1 + R2

Suppose the required operation is: 


R3 <= R1 + R2;

The control logic must configure the datapath so that:

  1. Select R1 as the first ALU operand.
  2. Select R2 as the second ALU operand.
  3. Select ADD as the ALU operation.
  4. Enable R3 to capture the result.

             Control Logic
                  |
       +----------+----------+
       |          |          |
       v          v          v
    Select A   ALU Op    Reg Enable
       |          |          |
       v          v          v
     +-------------------------+
     |                         |

     |          ALU            |----> R3
R2 ->|                         |
     |                         |
     +-------------------------+

Control Path + Datapath

A useful way to think about the relationship is: 


        Control Path
             |
             | Control Signals
             v
      +----------------+
      |    Datapath    |
      |                |
      | Reg → MUX → ALU |
      |       → Reg    |
      +----------------+
             |
             v
        Processed Data

The control path does not normally perform the arithmetic itself. Instead, it configures the datapath to perform the required operation.

Connection to FSMs

The FSM concepts from Lesson 6 are directly useful here. A controller can use different states to generate different control signals for different datapath operations. For example: 


IDLE
  |
  v
LOAD
  |
  v
EXECUTE
  |
  v

  |
  v

Each state can activate a different set of control signals. This creates a common architecture where: 


             +----------------+
             |  Control FSM   |
             +----------------+
                     |
              Control Signals
                     |
                     v
             +----------------+
             |    Datapath    |
             +----------------+
                     |
                  Result

Key Idea

The datapath performs the operation, while the control logic configures and sequences that operation.

This control + datapath relationship is fundamental to many RTL designs, processors and SoC blocks.

10. Single-Cycle Datapath Concept

Understanding how a complete datapath operation can occur within one clock cycle.

What is a Single-Cycle Datapath?

In a single-cycle design, a complete operation is performed within one clock cycle. The required datapath components are arranged so that data can travel from the source registers through the required combinational logic and reach the destination before the next active clock edge.

Basic Concept 


        Source Register
              |
              v
             MUX
              |
              v
             ALU
              |
              v
        Destination Register
              |
              v
        Next Clock Edge

The combinational logic between the registers determines how much time is required for the operation to complete.

Example

Consider the operation: 


R3 <= R1 + R2;

During the clock cycle:

  1. R1 provides the first operand.
  2. R2 provides the second operand.
  3. The ALU performs the addition.
  4. The result propagates through the combinational logic.
  5. R3 captures the result at the next active clock edge.

        R1 --------\
                    \
                     +---------+
        R2 -------->|   ALU   |------> R3
                     +---------+
                         |
                         |
                  Combinational
                    Operation

        |------------- One Clock Cycle -------------|

Clock Perspective 


Clock:

     ↑                 ↑
     |                 |
-----|-----------------|-----
     |                 |
     |<-- One Cycle -->|
     
     R1/R2             R3
     values            captures
     available         result
          \           /
           \         /
            \       /
             ALU

The source registers provide stable values during the cycle. The combinational datapath processes those values, and the destination register captures the result at the next clock edge.

Critical Path

The longest combinational path between two registers is called the critical path. For example: 


Register
   |
   v
  MUX
   |
   v
  ALU
   |
   v
Register

If the MUX and ALU together form the longest combinational delay, they can determine the minimum clock period for that datapath.

Single-Cycle Advantage

  • Simple control structure.
  • Each operation completes in one clock cycle.
  • Easy to understand conceptually.

Single-Cycle Limitation

  • The clock period must accommodate the longest operation.
  • Short operations may still use the same long clock period.
  • Large combinational paths can limit the maximum clock frequency.

Relationship to RTL

At the RTL level, a single-cycle datapath can still contain both sequential and combinational logic. Registers provide the clocked boundaries, while the logic between them performs the operation. 


       Sequential       Combinational       Sequential

       +--------+       +-------------+       +--------+
       | Source | ----> | MUX + ALU   | ----> | Dest.  |
       | Regs   |       |             |       | Reg    |
       +--------+       +-------------+       +--------+
            |                                      |
            +-------------- Clock -----------------+

Key Idea

In a single-cycle datapath, the complete combinational operation must fit between two clocked register boundaries within one clock cycle.

The longest combinational delay affects the minimum clock period.

11. Multi-Cycle Datapath Concept

Understanding how a complex operation can be divided across multiple clock cycles.

What is a Multi-Cycle Datapath?

In a multi-cycle datapath, a complete operation is divided into multiple smaller steps. Each step can execute during a different clock cycle. This allows hardware resources to be reused across different operations and can reduce the amount of combinational logic required in a single cycle.

Simple Concept 


Clock Cycle 1
     |
     v
Load Data
     |
     v
Clock Cycle 2
     |
     v
Process Data
     |
     v
Clock Cycle 3
     |
     v
Store Result

Example

Consider: 


R3 <= R1 + R2;

A simplified multi-cycle implementation could divide the operation into:

  1. Read or load the first operand.
  2. Read or load the second operand.
  3. Perform the ALU operation.
  4. Store the result.

The exact number of cycles depends on the architecture and design requirements.

Multi-Cycle Datapath Example 


             +-------------+
             |  Registers  |
             +-------------+
                    |
                    v
             +-------------+
             |     MUX     |
             +-------------+
                    |
                    v
             +-------------+
             |     ALU     |
             +-------------+
                    |
                    v
             +-------------+
             |   Register  |
             +-------------+

        Control FSM
             |
             v
      Control Signals

The control FSM can generate different control signals during each cycle. For example: 


Cycle 1 → LOAD

Cycle 2 → EXECUTE

Cycle 3 → WRITE

Connection Between FSM and Datapath

This is where the concepts from Lesson 6 become especially useful. The FSM acts as the control path, while the datapath performs the actual data operations. 


             +----------------+
             |   Control FSM  |
             +----------------+
                     |
                     |
              Control Signals
                     |
                     v
             +----------------+
             |    Datapath    |
             |                |
             | Registers      |
             | MUXes          |
             | ALU            |
             +----------------+
                     |
                     v
                   Result

Single-Cycle vs Multi-Cycle

Single-Cycle Multi-Cycle
Operation completes in one cycle. Operation is divided across multiple cycles.
Can require a long combinational path. Can use shorter combinational paths per cycle.
Control can be simpler. Requires sequencing across multiple cycles.
Hardware may need to support the complete operation in one cycle. Hardware resources can potentially be reused.

Why Use Multi-Cycle Datapaths?

  • Break complex operations into smaller steps.
  • Reduce the amount of combinational logic active in one cycle.
  • Allow hardware resources to be reused.
  • Provide more flexibility in controlling complex operations.

Key Idea

A multi-cycle datapath divides a larger operation into smaller clocked steps, with a control FSM coordinating the datapath during each cycle.

This creates a direct connection between the FSM concepts from Lesson 6 and the datapath concepts in this lesson.

12. Datapath RTL Example

Putting registers, an ALU and control signals together in synthesizable Verilog RTL.

Datapath Specification

Let's design a simple 8-bit datapath that can perform basic arithmetic and logical operations. The datapath will contain:

  • Two 8-bit input registers.
  • An ALU.
  • An 8-bit result register.
  • An operation-select signal.
  • A register enable signal.
  • A reset signal.

011 → OR

Complete Verilog RTL 


module simple_datapath (

    input wire clk,
    input wire reset,
    input wire enable,

    input wire [7:0] data_a,
    input wire [7:0] data_b,

    input wire [2:0] alu_op,

    output reg [7:0] result

);

reg [7:0] reg_a;
reg [7:0] reg_b;

reg [7:0] alu_result;


// =====================================
// Input Registers
// =====================================

always @(posedge clk) begin

    if (reset) begin

        reg_a <= 8'b0;
        reg_b <= 8'b0;

    end

    else if (enable) begin

        reg_a <= data_a;
        reg_b <= data_b;

    end

end


// =====================================
// ALU
// =====================================

always @(*) begin

    case (alu_op)

        3'b000:
            alu_result = reg_a + reg_b;

        3'b001:
            alu_result = reg_a - reg_b;

        3'b010:
            alu_result = reg_a & reg_b;

        3'b011:
            alu_result = reg_a | reg_b;

        3'b100:
            alu_result = reg_a ^ reg_b;

        default:
            alu_result = 8'b0;

    endcase

end


// =====================================
// Result Register
// =====================================

always @(posedge clk) begin

    if (reset)

        result <= 8'b0;

    else if (enable)

        result <= alu_result;

end

endmodule

How the RTL Works

  1. At reset, the input registers and result register are cleared.
  2. When enable = 1, the input values are captured into reg_a and reg_b.
  3. The combinational ALU continuously calculates the result according to alu_op.
  4. On the next active clock edge, the calculated ALU result is captured into the result register.

Example 


data_a = 10

data_b = 5

alu_op = 000

enable = 1

The ALU operation is ADD: 


10 + 5 = 15

The result register will capture the calculated value on the appropriate clock edge. Therefore: 


result = 15

Important RTL Observation

Notice that the ALU is combinational, while the registers are sequential. This separation is a fundamental RTL design pattern:

      v
   Registers
      |
      v

      |
      v
   ALU Result
      |
      v
Sequential Logic
      |

   Register

Key Idea

A datapath combines sequential storage elements with combinational processing logic to move and transform data across clock cycles.

13. Datapath Timing

Understanding how clock period, propagation delay and setup time affect datapath operation.

Why Timing Matters

A synchronous datapath must complete its combinational operation within the available clock period. The receiving register must have enough time to capture the result correctly at the next active clock edge.

Basic Timing Path 


Source Register
      |
      | Clock-to-Q Delay
      v
Combinational Logic
      |
      | Propagation Delay
      v
Destination Register
      |
      | Setup Time
      v
Next Clock Edge

Example Datapath 


     +--------+       +-----------+       +--------+
     | Reg A  | ----> |    ALU    | ----> | Reg B  |
     +--------+       +-----------+       +--------+
         |                  |
         |                  |
     Clock-to-Q        Combinational
                         Delay

The data launched by the source register must propagate through the combinational logic and arrive at the destination register early enough to satisfy its setup-time requirement.

Simplified Timing Requirement 


Clock Period ≥

Clock-to-Q Delay
+
Combinational Logic Delay
+
Setup Time
+
Timing Margin

For a simplified example, suppose:

  • Clock-to-Q delay = 1 ns
  • ALU and other combinational delay = 5 ns
  • Setup time = 1 ns
  • Timing margin = 1 ns

Then the minimum clock period would need to be approximately: 


1 ns + 5 ns + 1 ns + 1 ns

= 8 ns

This corresponds to a theoretical maximum frequency of approximately: 


Frequency = 1 / Clock Period

          = 1 / 8 ns

          = 125 MHz

Critical Path

In a datapath containing multiple register-to-register paths, the critical path is the path with the largest timing delay. 


             Path 1
Reg ----> MUX ----> Reg
          2 ns

             Path 2
Reg ----> MUX ----> ALU ----> Reg
          2 ns      5 ns

             Path 3
Reg ----> ALU ----> Reg
          4 ns

In this example, Path 2 has the largest combinational delay and is therefore the likely critical path.

What Happens If the Path Is Too Slow?

If data does not arrive at the destination register before the setup requirement, a setup timing violation can occur. This means the design may not operate reliably at the intended clock frequency.

How Can Datapath Timing Be Improved?

  • Reduce unnecessary combinational logic.
  • Optimize arithmetic operations.
  • Reduce multiplexer depth.
  • Use pipelining to divide long paths.
  • Optimize the critical path.

Connection to Pipelining

If a combinational path is too long, pipeline registers can divide the operation into multiple stages. 


Without Pipeline:

Reg --------> MUX ----> ALU ----> Logic --------> Reg


With Pipeline:

Reg ----> MUX ----> Reg ----> ALU ----> Reg
                     ^
                     |
                 Pipeline
                 Register

Pipelining can reduce the amount of combinational work performed in each clock cycle, allowing a shorter clock period.

Key Idea

A datapath must satisfy timing requirements between its sequential elements. The longest register-to-register path often determines the maximum operating frequency.
