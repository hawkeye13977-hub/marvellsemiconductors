What is a Procedural Block?

Understanding how Verilog describes procedural hardware behavior.

A procedural block is a section of Verilog code containing statements that execute when a specified event occurs.

The most commonly used procedural construct for RTL design is the always block.

Basic Structure 

always @(sensitivity_list) begin

    // RTL statements

end

The sensitivity information determines when the procedural block is triggered.

The always Block

The fundamental procedural construct used in Verilog RTL.

The always block repeatedly executes whenever its specified triggering event occurs.

Combinational Example 

always @(*) begin

    y = a & b;

end

Sequential Example 

always @(posedge clk) begin

    q <= d;

end
Type Typical Block Purpose
Combinational always @(*) Logic based on current inputs
Sequential always @(posedge clk) Clocked state storage

Blocking Assignment (=)

Understanding how blocking assignments execute inside procedural blocks.

A blocking assignment uses the = operator. The assignment updates the left-hand side immediately within the procedural flow of the block.

Basic Syntax 

always @(*) begin

    y = a & b;

end

Example 

always @(*) begin

    x = a;
    y = x;

end

The statements execute in order. First: x = a is executed. Then: y = x uses the updated value of x.

Important Concept

Blocking assignments execute sequentially inside the procedural block. The next statement sees the value assigned by the previous statement.

Where is Blocking Assignment Commonly Used?

  • Combinational logic.
  • Temporary variables inside combinational calculations.
  • Procedural calculations where statement ordering matters.

RTL Rule

For combinational logic written using always @(*), blocking assignment = is commonly used.

Non-Blocking Assignment (<=)

Understanding the assignment style commonly used for sequential RTL.

A non-blocking assignment uses the <= operator. It is commonly used to describe clocked sequential logic such as flip-flops, registers and counters.

Basic Syntax 

always @(posedge clk) begin

    q <= d;

end

Example 

always @(posedge clk) begin

    q1 <= d1;
    q2 <= q1;

end

At the clock edge, the right-hand-side values are evaluated using the current state, and the updates are scheduled for the non-blocking assignment update region.

Therefore, in the example above, q2 receives the previous value of q1, rather than the value assigned to q1 during the same clock event.

Where is Non-Blocking Assignment Used?

  • Flip-flops.
  • Registers.
  • Counters.
  • Finite State Machines.
  • Other clocked sequential logic.

RTL Rule

For clocked sequential logic, use non-blocking assignment (<=) to model state updates.

Why Does This Matter?

Consider a two-stage register pipeline: 

always @(posedge clk) begin

    stage1 <= data;
    stage2 <= stage1;

end

The first stage captures the current value of data. The second stage captures the previous value of stage1. This models how two flip-flops connected in sequence behave in hardware.

Key Idea

Non-blocking assignment allows multiple sequential elements to update as if they respond to the same clock edge.

Blocking (=) vs Non-Blocking (<=)

Understanding the most important Verilog assignment rule for RTL design.

Blocking Assignment (=)

  • Uses the = operator.
  • Statements execute in procedural order.
  • The next statement sees the updated value.
  • Commonly used for combinational logic.
always @(*) begin

    a = b;
    c = a;

end

Here, c sees the value assigned to a by the previous statement.

Non-Blocking Assignment (<=)

  • Uses the <= operator.
  • Updates are scheduled rather than immediately visible to following statements.
  • Models simultaneous state updates at a clock edge.
  • Commonly used for sequential logic.
always @(posedge clk) begin

    a <= b;
    c <= a;

end

Here, c receives the previous value of a.

Quick Comparison

Feature Blocking (=) Non-Blocking (<=)
Operator = <=
Execution behavior Procedural order Updates are scheduled
Common RTL usage Combinational logic Sequential logic
Typical block always @(*) always @(posedge clk)
Typical hardware Combinational logic Flip-flops / registers

Important Example 

always @(posedge clk) begin

    q1 <= d;
    q2 <= q1;

end

Suppose before the clock edge: 

q1 = 0
q2 = 0
d  = 1

At the rising edge: 

q1 <= 1
q2 <= 0

After the update: 

q1 = 1
q2 = 0

On the next clock edge, q2 can capture the new value of q1. This behavior represents a simple two-stage pipeline.

RTL Golden Rule

Combinational logic → Blocking (=)

Sequential logic → Non-Blocking (<=)
